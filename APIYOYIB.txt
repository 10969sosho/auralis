                                <div class="panel-heading">
                                    <h4 class="panel-title">
                                        <a id="apl">
                                            API Process Flow
                                        </a>
                                    </h4>
                                </div>
                                <div class="panel-body">
                                    <p>You will interact a lot with <strong>Category</strong> and <strong>Bill</strong>.</p>
                                    <p>Category is a group of bills. You can create a category based on bills type. e.g. House rental, Subscription fees.</p>
                                    <p>A bill is an invoice for your customer. A bill must belong to a Category</p>
                                    <p>
                                        To start using the API, you would have to create a Category. Then the payment flow will kicks in as per below:
                                    </p>
                                    <ul>
                                        <li>Customer visits your site.</li>
                                        <li>Customer chooses to make payment.</li>
                                        <li>Your site creates a Bill via API call.</li>
                                        <li>toyyibPay API returns Bill's code.</li>
                                        <li>Your site redirects the customer to Bill's URL.</li>
                                        <li>The customer makes payment via payment option of choice.</li>
                                        <li>toyyibPay sends a server-side update (Payment Completion) to your site on Bill's status on payment failure or success.</li>
                                        <li>Your site can check payment status via API call</li>
                                    </ul>

                                    <h4 class="panel-title">
                                        <a id="cb">
                                            Create Bill
                                        </a>
                                    </h4>
                                </div>
                                <div class="panel-body">
                                    <p>Bill serves as an invoice to your customer.</p>
                                    <p>In the example below, we will show you how to create a Bill. You need to pass the following parameters to generate bill code. </p>
                                    <ul>
                                        <li><strong>userSecretKey</strong> - User Secret Key</li>
                                        <li><strong>categoryCode</strong> - Category Code. Get your Category Code from Create Category API</li>
                                        <li><strong>billName</strong> - Your bill name. Bill Name will be displayed as bill title<br><small class="text-danger">* Max 30 alphanumeric characters, space and '_' only </small></li>
                                        <li><strong>billDescription</strong>- Your bill description.<br><small class="text-danger">* Max 100 alphanumeric characters, space and '_' only </small></li>
                                        <li><strong>billPriceSetting</strong> - For fixed amount bill, set it to 1 and insert bill amount. For dynamic bill (user can insert the amount to pay), set it to 0.</li>
                                        <li><strong>billPayorInfo</strong> - If you want to create open bill without require payer information, set it to 0. If you need payer information, set it to 1</li>
                                        <li><strong>billAmount</strong> - Key in the bill amount. The amount is in cent. e.g. 100 = RM1. If you set billPriceSetting to 0 (dynamic bill), please put 0</li>
                                        <li><strong>billReturnUrl</strong> - Key in return Url if you need the bill to be redirected to your own page upon payment completion.</li>
                                        <li><strong>billCallbackUrl</strong> - Key in callback url if you need the bill to be redirected to your callback page upon sucessful of payment transaction.</li>
                                        <li><strong>billExternalReferenceNo</strong> - Provide your own system reference no if you think it is required. You may use this reference no to check the payment status for the bill.</li>
                                        <li><strong>billTo</strong> - If you intend to provide the bill to specific person, you may fill the person nam in this field. If not, please leave it blank.</li>
                                        <li><strong>billEmail</strong> - Provide your customer email here</li>
                                        <li><strong>billPhone</strong> - Provide your customer phone number here.</li>
                                        <li><strong>billSplitPayment</strong> - [OPTIONAL] Set 1 if the you need the payment to be splitted to other toyyibPay users. This function is not available for billPriceSetting = 0 (dynamic bill).</li>
                                        <li><strong>billSplitPaymentArgs</strong> - [OPTIONAL] Provide JSON for split payment. e.g. [{"id":"johndoe","amount":"200"}]</li>
                                        <br>
                                        <p>*Please note that Split Payment is available for Online Banking (FPX) only.</p>
                                        <li><strong>billPaymentChannel</strong> - Set 0 for FPX, 1 Credit Card and 2 for both FPX &amp; Credit Card.</li>
                                        <li><strong>billContentEmail</strong> - [OPTIONAL] Provide additional messages by sending an extra email to your customer. Limited to 1000 characters only.</li>
                                        <li><strong>billChargeToCustomer</strong> - [OPTIONAL] Below are the values available :
                                            <p>1. Leave blank to set charges for both FPX and Credit Card on bill owner.<br>
                                                2. Set "0" to charge FPX to customer.<br>
                                                * charge to customer is not available for card payment channel</p>
                                        </li>
                                        <li><strong>billChargeToPrepaid</strong> - [OPTIONAL] Deducts the transaction charge from the prepaid account. Applicable only for FPX when charges are set to the bill owner.</li>
                                        <li><strong>billExpiryDate</strong> - [OPTIONAL] Date and time to set the bill as inactive (expired). Payer will not be able to make payment after the expiry date. Here is the datetime sample value: "17-12-2020 17:00:00".</li>
                                        <li><strong>billExpiryDays</strong> - [OPTIONAL] Number of day(s) to allow payment attempt to be made. The bill will be set to inactive after the number of day(s). The default expiry time will be at 23:59:59 on the final day. This parameter is ranged between minimum 1 day to maximum 100 days. The billExpiryDate parameter will be prioritised if both billExpiryDays and billExpiryDate parameters are set.</li>
                                        <li><strong>enableFPXB2B</strong> - [OPTIONAL] Set "1" to enable FPX (Corporate Banking) payment channel.</li>
                                        <li><strong>chargeFPXB2B</strong> - [OPTIONAL] Charge for FPX (Corporate Banking) payment channel :
                                            <p> 1. Set "0" for charge to customer.<br>
                                                2. Set "1" for charge on bill owner.<br>
                                                * Default value is "1" which is charge on bill owner, if parameter "enableFPXB2B" is set to "1".</p>
                                        </li>
                                        <li><strong>enableDuitNowQR</strong> - [OPTIONAL] Set "1" to enable DuitNow QR payment channel. Your account must have DuitNow QR activated.</li>
                                        <li><strong>chargeDuitNowQR</strong> - [OPTIONAL] Required when <strong>enableDuitNowQR</strong> is set to "1". Below are the values available :
                                            <p> 1. Set "0" for charge on bill owner.<br>
                                                2. Set "1" for charge to customer.</p>
                                        </li>
                                    </ul>
                                    <p>Our API system will return Bill Code in JSON format. In this example, the API return <strong>gcbhict9</strong> as bill code. Hence, your payment url will be:- https://toyyibpay.com/<strong>gcbhict9</strong></p>

                                <div class="panel-heading">
                                    <h4 class="panel-title">
                                        <a id="cp">
                                            Callback Parameter
                                        </a>
                                    </h4>
                                </div>
                                <div class="panel-body">
                                    <p>Please note that Callback URL <b>cannot</b> be received in localhost. Callback URL will be supplied with the following datas in POST format:-</p>
                                    <p><strong>refno</strong> : Payment reference no</p>
                                    <p><strong>status</strong> : Payment status. 1= success, 2=pending, 3=fail</p>
                                    <p><strong>reason</strong> : Reason for the status received</p>
                                    <p><strong>billcode</strong> : Your billcode / permanent link</p>
                                    <p><strong>order_id</strong> : Your external payment reference no, if specified</p>
                                    <p><strong>amount</strong> : Payment amount received</p>
                                    <p><strong>transaction_time</strong> : Datetime of the transaction status received.</p>
                                    <p><strong>hash</strong> : MD5 hash for callback verification. You <strong>must</strong> validate this before processing the payment.</p>
                                    <br>
                                    <p><strong>Hash Validation</strong></p>
                                    <p>Generate the expected hash using the formula below and compare it against the received <strong>hash</strong> value:</p>
                                    <pre><code>MD5( userSecretKey + status + order_id + refno + "ok" )</code></pre>
                                    <p>Example (PHP):</p>
                                    <pre><code>&lt;?php
$expected_hash = md5( $userSecretKey . $status . $order_id . $refno . "ok" );

if ( $received_hash === $expected_hash ) {
    // Valid - safe to process payment
} else {
    // Invalid - reject request
}
?&gt;</code></pre>
                                    <br>
                                    <div class="alert alert-info">
                                        <i class="fa fa-info-circle"></i> <strong>DuitNow QR:</strong> DuitNow QR payments send a similar callback with the following parameters: <strong>refno</strong>, <strong>status</strong>, <strong>reason</strong>, <strong>billcode</strong>, <strong>order_id</strong>, <strong>amount</strong>, <strong>status_id</strong>, <strong>msg</strong>, <strong>transaction_id</strong> (toyyibPay invoice number), <strong>dnqr_transaction_id</strong> (DuitNow QR transaction ID), and <strong>hash</strong>. Note: DuitNow QR callbacks do not include <strong>transaction_time</strong> or <strong>fpx_transaction_id</strong>. You can identify DuitNow QR payments via <strong>billpaymentChannel = "DuitNow QR"</strong> in the <a href="#gbt">Get Bill Transactions</a> API.
                                    </div>
